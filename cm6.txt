chore: the editor tool stops shipping, and the dead code that was really dead

PRIORITY 6 of the engineering-practices goal. Three findings from the audit, checked against the
tree before acting on any of them -- and one of them turned out to be wrong, which is why the
checking is the point.

## The Godot AI editor helper was being loaded by the game

`project.godot` declared `_mcp_game_helper="*res://addons/godot_ai/runtime/game_helper.gd"`, and NO
script in this project references it. Its own header says what it is:

    Registered as an autoload by plugin.gd when the Godot AI plugin is enabled.

So the plugin registers it when the plugin is on. Declaring it in `project.godot` forced it into
every run of the game and every one of the 18 battery runs with the plugin off -- an editor-side
screenshot relay carried by the shipped game. Removed, with the line and the reason left as a
comment so it can be restored in one paste. The boot log no longer shows its "registered mcp
capture" line, and --playground-check still passes 11 OK / 0 FAIL.

## Three functions were dead. Two were not.

The audit listed five functions with exactly one occurrence project-wide. Counting occurrences only
says "nothing calls this from a script in this tree"; it does not say whether the function is
waste or an interface waiting for a caller. Read one by one:

  * `ordered_surfaces` (wheelbarrow.gd) -- KEPT. Its own docstring says `--container-lab` measures
    the barrow against this list rather than against numbers copied into the test. That battery is
    parked, not cancelled, and deleting its interface would make the parked work harder to resume
    for no gain.
  * `is_mouth_at` (disposal_machine.gd) -- KEPT. Its docstring says the container interaction asks
    it before calling `accept`. The container interaction is the parked work. Same reasoning.
  * `_diag_tick` (disposal_machine_demo.gd) -- REMOVED, along with the `_last_diag` field and its
    reset. Its timer reset used the absolute phase clock, which resets every phase, so it could
    never have fired as intended: waste that did not even work.
  * `is_load_and_push_mode` (player_controller.gd) -- REMOVED. An accessor nothing reads, added in
    this session. If something needs it, one line brings it back.
  * `_ph_push_wait` (shovel_modes_demo.gd) -- REMOVED. An empty phase function that nothing
    dispatched to. It was a leftover from renumbering the phase machine, and a no-op phase in a
    file whose phases ARE the test is a thing that reads like a step and is not one.
