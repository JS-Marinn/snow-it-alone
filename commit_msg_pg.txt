fix: the Playground gets the reticle, and bare hands can throw

Two things the owner reported that the level's fixes never reached.

## The reticle did not appear in the Playground

Not broken: ABSENT. `scripts/playground.gd` said so in a comment -- "The Playground has no HUD"
-- and `_build_overlay` only builds a debug ledger. The reticle is drawn by the HUD, so with no
HUD there was nothing to draw, while snow and physics worked and made the scene look fine.

The HUD is now DECLARED IN `scenes/playground.tscn`, the full subtree copied from `main.tscn`,
because `hud.gd` reaches for a dozen child nodes by path in its `@onready` block. Building a bare
`CanvasLayer` with that script attached was tried first and failed on every one of them
("Node not found: MarginContainer/VBoxTop/Title"). Declaring it keeps the two scenes in step: if
the HUD grows a node, the scene file that is missing it says so at load.

Measured in the Playground's own PNG, which is the only check that counts for something visual:

    HUD node present: true
    HUD built its reticle: dot=true ring=true
    dot at (640, 360) rgb (0.094, 0.573, 0.761) luma 0.476 | snow 0.969 | contrast 0.493 | offset (0.0, 0.0) px
    VERDICT: the reticle IS visible in the Playground (contrast 0.493)

`--pg-reticle-probe` is the instrument that produced that, and it also brings the coin and
"snow sent" counters to the Playground with the HUD they belong to.

## Bare hands could not throw

`_throw_carried` was always able to throw. The only code that LISTENED for the throw button was
`_update_shovel_buttons`, which runs from `_process_shovel` and therefore only with a shovel
equipped. In the tool dispatch, `ToolType.HANDS` was `pass` -- so a player who packed a ball by
hand and picked it up had no way to throw it: the button did nothing.

`_update_hands_throw` reads the same input and calls the same `_throw_carried`, so a ball leaves
the hands at exactly the speed and angle it does from a shovel. The shovel's tap-to-toss and
hold-to-pour are deliberately not duplicated: those act on a loaded shovel and there is none.

## State of the gate

Unchanged by this commit: 15 of 18 batteries pass, including --reticle-aim 23/0, --hand-pack
12/0, --reticle-act 33/0, --playground-check 11/0. The three that fail are the same three as
before and are the anti-soft-lock chain, documented in `tool_ownership_demo.gd`: the Playground
scene is loaded on top of the level mid-run, which takes the tree and the thrown ball with it.
--reticle-act failed once in a previous gate run with a "no verdict" verdict and passed in this
one, so that is recorded as intermittent rather than fixed.
